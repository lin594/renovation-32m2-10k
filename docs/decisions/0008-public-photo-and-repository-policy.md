# 0008：公开范围、照片与互动边界

- 状态：已采纳
- 日期：2026-09-01

## 背景

仓库既要让业主和 AI 持续维护，也要让陌生访客看懂 32㎡ 老房如何在低预算、异地施工和三猫安全约束下推进。真实现场照片能提供图纸无法替代的前后证据，但原件包含设备、时间等不必要元数据，直接提交也会扩大体积和隐私风险。

## 决策

1. 仓库继续公开，接受既有房屋布局、楼层、时间计划和 Git 历史已经公开的事实；不重写历史，不更改真实提交邮箱。
2. HEIC 原件只保存在 `.local/photos-original/`，不进入 Git。公开照片统一为自动旋转、最长边 1800px、sRGB、质量 82、4:2:0、渐进式且清除元数据的 JPEG，单文件不超过 900KB。
3. 可识别人像必须在公开前遮挡。照片以 `data/photos.csv` 为目录真源，按房间、日期、阶段和机位组织；`media/photos/README.md` 由脚本生成，不虚构未拍摄阶段。
4. README 只链接图库，不直接加载现场照片；前后对比优先使用相同机位和方向的真实记录。
5. 通过 GitHub Issues 接受建议，不主动征集 Pull Request；不启用 Discussions、空贡献指南或 Issue 模板。
6. 仓库不采用标准开源许可证。`© 2026 lin594. All rights reserved.`；除 GitHub 平台条款允许的浏览与 fork 外，不授予复制、修改、再发布或商业使用权。
7. 不启用 Git LFS。当前公开照片体量很小，普通 Git 更方便 README、克隆和未来静态展示。

## 影响

公开仓库获得可核验的现场证据和更清楚的对外入口；新增照片必须经过导入、隐私检查和图库重建。未公开原件仍需由业主自行备份，Git 不能承担原始照片归档职责。
