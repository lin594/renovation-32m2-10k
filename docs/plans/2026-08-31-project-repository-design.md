# 装修项目仓库设计

## 目标

该仓库覆盖购房后到可入住的完整过程。设计采用“机器可读数据 + 人类可读决策 + 可版本化图纸”三层结构：`house.yaml` 保存空间和固定点位，`data/` 保存持续变化的账目、进度、库存和风险，`docs/` 解释关键选择，`diagrams/` 输出面向人的 SVG。这样既能进行程序化校验，又能让现场施工人员快速查看。

## 数据流

现场事实先进入对应真源文件，再同步到相关 SVG 或决策文档。金额只在 `data/ledger.csv` 录入一次，汇总由脚本生成 `PROJECT_STATUS.md`，避免手写总计漂移。每个逻辑变化通过独立 Git 提交保存，提交范围与房间或流程阶段对应。`diagrams/` 只保留现行图纸，历史图纸由 Git 记录追溯。

## 状态与异常

项目明确区分已确认、计划、TODO、受阻和完成。缺尺寸、口述冲突或安全条件不明时，不用默认值覆盖，而是登记风险和下一步核验动作。燃气、电气、防水、承重等高风险信息只做事实记录和方案比较，不能把未验收的设想标成可施工。

## 验证

`make check` 检查必需文件、账目字段、重复 ID、金额格式、派生状态和 SVG/XML；`make summary` 输出唯一账本的累计支出、收入和净现金流。GitHub Actions 在主分支自动同步状态页。所有提交前必须执行校验。未来如增加采购订单和工期依赖，可在同一模式下扩充 CSV/YAML 与校验器，而不引入数据库。
